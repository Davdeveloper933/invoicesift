# Сайт для проверки идеи: запуск, публикация, защита

Сайт находится в папке `web/`. Посетитель:

1. видит лендинг;
2. бесплатно пробует **8 счетов** (или 10 готовых примеров, они ничего не стоят);
3. после 8-го счёта видит окно: «как отработало», «что не так / чего не хватает», «заплатили бы $19/мес» (да / только если дешевле / нет), email;
4. в разделе Pricing может «зарезервировать» место по единственному тарифу: $19/мес за 500 счетов. Денег не берём, это проверка спроса.

Вся статистика на странице `/admin`: воронка, тарифы, источники трафика, отзывы, email'ы, выгрузка в CSV.

## 1. Запуск у себя на компьютере

Из папки `E:\Projects\invoice-extractor`:

```bash
.venv\Scripts\python.exe -m pip install -r requirements-web.txt
```

```bash
.venv\Scripts\python.exe -m uvicorn web.app:app --port 8000
```

Откройте http://localhost:8000. Для админки добавьте в `.env` строку `ADMIN_TOKEN=` с паролем **не короче 16 символов** и откройте http://localhost:8000/admin.

## 2. Публикация в интернете бесплатно (Render + Neon)

### Шаг 1. Отдельный ключ OpenAI с лимитом расходов (обязательно)
1. На https://platform.openai.com/api-keys создайте **новый** ключ только для сайта.
2. Отзовите (Revoke) старый ключ, который был в чате.
3. В **Settings → Limits** поставьте месячный лимит, например $10. Даже если кто-то обойдёт все защиты сайта, больше этой суммы потратить не получится.

### Шаг 2. Бесплатная база данных Neon
У бесплатного Render диск очищается при каждом перезапуске. Без внешней базы вы потеряете email'ы и отзывы.
1. Зарегистрируйтесь на https://neon.tech и создайте проект (Free).
2. Скопируйте **Connection string**, она выглядит как `postgresql://...neon.tech/neondb?sslmode=require`.

### Шаг 3. Код на GitHub

**Вариант А: через браузер, без программ.** Чистая копия для загрузки лежит в `E:\Projects\invoice-extractor-github` (без `.env`, `.venv`, базы и логов).
1. github.com → **New repository** → имя `invoicesift`, **Private**, ничего не добавлять → Create.
2. На странице репозитория ссылка **uploading an existing file**.
3. Откройте `E:\Projects\invoice-extractor-github`, выделите **всё содержимое** (Ctrl+A, не саму папку) и перетащите в окно браузера.
4. Дождитесь, пока загрузятся все файлы, внизу нажмите **Commit changes**.
5. Проверьте: в корне репозитория должны быть `render.yaml` и папка `web`, а файла `.env` быть не должно.

Обновить сайт позже: снова Add file → Upload files, перетащить изменённые файлы. Render передеплоит сам.

**Вариант Б: GitHub Desktop.**
1. Установите **GitHub Desktop** (https://desktop.github.com) и войдите.
2. File → Add local repository → `E:\Projects\invoice-extractor` → «create a repository».
3. Publish repository, галочка **Keep this code private**.
4. Файл `.env` с ключом **не попадёт** на GitHub: он в `.gitignore`. Проверьте, что в списке файлов GitHub Desktop его нет.

### Шаг 4. Render
1. Зарегистрируйтесь на https://render.com через GitHub.
2. New → **Blueprint** → выберите ваш репозиторий. Render прочитает `render.yaml`.
3. Он попросит две переменные:
   - `OPENAI_API_KEY`: новый ключ из шага 1;
   - `DATABASE_URL`: строка из Neon.
4. Apply. Через 3–5 минут сайт будет доступен по адресу вида `https://invoicesift.onrender.com`.
5. Пароль админки: Render → ваш сервис → **Environment** → `ADMIN_TOKEN` (сгенерирован автоматически). Откройте `https://...onrender.com/admin` и введите его.

Бесплатный Render «засыпает» через 15 минут без посетителей. Первый заход после этого грузится 30–60 секунд. Для проверки идеи это нормально. Если начнёт мешать, тариф за $7/мес это убирает.

### Шаг 5. Двухфакторная защита аккаунтов
Включите 2FA на GitHub, Render, Neon и OpenAI. Чаще всего сайты взламывают не через код, а через украденный пароль от аккаунта.

## 3. Как получить посетителей и понять, есть ли спрос

Давайте ссылку с меткой источника, и в админке будет видно, откуда пришли люди:

- `https://ваш-сайт/?ref=reddit`
- `https://ваш-сайт/?ref=linkedin`
- `https://ваш-сайт/?ref=upwork`

Где искать аудиторию: r/Bookkeeping, r/Accounting, r/smallbusiness, группы бухгалтеров в LinkedIn и Facebook, личные сообщения бухгалтерам-фрилансерам.

**Ориентиры для решения** после ~200–300 посетителей из целевой аудитории:

| Метрика | Слабо | Хорошо |
|---|---|---|
| Попробовали демо | < 15% | > 30% |
| Оставили email | < 3% | > 8–10% |
| Ответили «Yes, $19/mo», а не «дешевле» или «нет» | < 30% | > 50% |
| Отзывы | «прикольно» | «мне нужно X, когда запуск?» |

Самый ценный сигнал: люди, которые обрабатывают **100+ счетов в месяц** и отвечают «Yes, $19/mo». Напишите каждому лично, это ваши первые клиенты. Если многие выбирают «only if cheaper», цену стоит пересмотреть.

## 4. Защита сайта: что сделано

Взломать нельзя только сайт, которого нет. Поэтому задача в том, чтобы закрыть все известные типовые атаки (список OWASP Top 10) и ограничить ущерб, если что-то всё-таки случится.

| Угроза | Защита |
|---|---|
| Кража ваших API-кредитов | 8 бесплатных счетов на посетителя (считаются и по браузеру, и по IP); общий дневной лимит `DEMO_GLOBAL_DAILY`; не больше 10 загрузок в час с одного IP; одна загрузка одновременно на посетителя; максимум 4 обработки одновременно на сервер; **плюс** лимит расходов в кабинете OpenAI |
| Владелец упирается в лимит сам | Браузер, из которого хоть раз вошли в `/admin`, работает в «режиме админа»: без лимита бесплатных счетов (до `DEMO_OWNER_MAX_FILES`=20 файлов за раз), его счета не тратят дневной лимит и не попадают в статистику |
| Внедрение вредного кода в страницу (XSS) | Строгая политика безопасности (CSP): браузер выполняет только скрипты с вашего сайта. Весь пользовательский текст выводится как текст, а не как HTML |
| Встраивание сайта в чужую страницу (clickjacking) | `X-Frame-Options: DENY`, `frame-ancestors 'none'` |
| Подбор пароля админки | Пароль не короче 16 символов, иначе админка выключена; 5 неверных попыток с одного IP дают блокировку на 15 минут; сравнение без утечки по времени |
| Спам-боты в формах | Скрытое поле-ловушка (honeypot); не больше 10 отправок в час с IP; ограничение длины каждого поля |
| Огромные файлы и «PDF-бомбы» | Загрузка больше ~31 МБ обрывается ещё до чтения; файл до 10 МБ, все файлы за раз до 30 МБ; проверка, что это действительно PDF; читаются только 3 страницы; размер картинки страницы ограничен |
| Подмена путей к файлам (`../../`) | Имена файлов очищаются; примеры отдаются только из своей папки |
| Утечка ключей и ошибок | Ключи только в переменных окружения; посетитель видит общее «не получилось», без деталей ошибки API; документация API и заголовок сервера скрыты |
| Перехват трафика | HTTPS на Render автоматически плюс HSTS (браузер больше не откроет сайт по HTTP) |
| Формулы в выгрузке CSV (атака через Excel) | Ячейки, начинающиеся с `= + - @`, экранируются |
| SQL-инъекции | Все запросы к базе идут через SQLAlchemy с параметрами, без склейки строк |
| Хранение лишних данных | Загруженные счета удаляются сразу после обработки; IP хранится только как хэш |

Основные из этих защит (лимиты, заголовки, блокировка админки, ловушка для ботов, размер запроса, CSV, утечка ошибок) проверяются автоматическими тестами в `tests/test_web.py`.

**Что остаётся на вас:**
- лимит расходов в OpenAI и 2FA на всех аккаунтах (шаги 1 и 5);
- не публиковать `.env` и пароль админки;
- периодически обновлять зависимости: `pip install -U -r requirements-web.txt`, затем тесты;
- если будете активно собирать email'ы посетителей из ЕС, добавьте страницу Privacy Policy (требование GDPR).
